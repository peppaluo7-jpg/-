# 跨语言关系沟通 Agent

生成表达现在通过一次模型调用完成意图、关系、文化画像、候选表达与风险自检；页面仍将这些结果分开展示，供用户核对。风险自检与生成来自同一次调用，并非独立模型复核。

## 三种产品形态

页面标题下方可以直接切换三种入口，三者共享当前浏览器中的用户偏好、联系人、历史往来、默认语气、文化画像和专属词汇：

- **独立网页端**：保留完整五步工作台，适合重要邮件、文化画像、多版本比较、逐句/逐词修改、风险核对和草稿保存。
- **浏览器 / 客户端内嵌**：在模拟邮件页面旁显示轻量 Agent。可读取当前邮件或选中文本，按联系人记忆一次生成表达，并回填邮件输入框。
- **双窗口关联联动**：左侧保留原聊天窗口，右侧同步用户勾选的多轮上下文。支持自动或手动同步，生成结果可以复制或回填原窗口。

轻量入口省去单独的信息提取和多页确认，直接使用已保存偏好与联系人记忆完成一次生成，以减少高频沟通场景下的等待和操作步骤。联系人中的专属称呼或项目词汇会用于保持指代一致；历史内容只作为语气和连续性参考，不会把旧事实、日期或承诺带入新表达。

## Demo 模式
如果没有 API Key，或完整生成过程中 API 调用失败，页面会标记 Demo 模式。Demo 只用于演示流程，不生成可发送的邮件正文，也不能核验语法、事实或文化适配；复制与保存草稿按钮会被禁用。

## 联系人记忆与编辑

- 在首页添加并选择联系人，可以载入关系、常用语境、表达尺度及曾明确保存的八项文化画像默认值。文化画像中的“保存为联系人默认”会记住已生成采用的值；微调滑块后需应用并重新生成成功，才会更新默认值。首次成功生成记录沟通目的和日期，随后微调不重复记录。联系人及历史仅保存在当前浏览器，可在页面中删除。
- 首页先填写偏好：你的姓名、候选数量、修改深度、关键语义确认，以及译文、解释和局部编辑需求。姓名和偏好保存在本机，信息确认页不再重复填写发送方姓名；信息提取也不会覆盖它。系统据此组织单一推荐、版本对比、细致编辑或高控制确认的界面路径，不显示手动工作模式切换器。
- 顶部以亮黄色线条显示五段进度，不再放置前后页操作按钮；各步骤在内容区提供继续入口。桌面上内容、信息确认与表达尺度横向三栏展示；确认生成表达后进入局部修改与风险/语义核对合并页。需要关键语义确认时，核对后才显示“准备草稿”；未启用该偏好时，风险检查区直接显示该按钮。修改正文会撤销此前的确认。不再单独展示表达原文卡片，也不在结果页切换标签。手机用页内切换组织填写步骤，长内容仅在内容区滚动。表达尺度均为 1–5，并显示当前档位解释。
- 逐句修改把前后文作为只读语境，只替换选中的句子；点击正文词语会打开可拖动的整句候选悬浮窗，建议附有语气标签、完整句子和词形、介词或搭配上的连带变化。点击候选只切换预览，确认后才替换当前句。AI 不可用时不展示未经整句校对的逐词候选。
- 选择“关键语义确认”后，须核对事实、立场和承诺才能进入草稿页。生成时风险自检不能代替独立复核，用户仍需在发送前自行核对最终结果。
- 草稿保存成功后才出现“再写一份”；它清空本次输入、生成内容和确认状态，但保留已填写的偏好与联系人记忆。

## AI 模式
在同级目录创建 `.env`：

```text
OPENAI_API_KEY=你的APIKey
OPENAI_MODEL=gpt-4o-mini
OPENAI_BASE_URL=https://api.openai.com/v1
```

如果你用的是非官方 OpenAI 兼容接口，可改成：

```text
OPENAI_API_KEY=你的Key
OPENAI_MODEL=你的模型名
OPENAI_BASE_URL=http://localhost:11434/v1
```

然后重新：
```powershell
python app.py
```

如果读取到配置会显示：
```text
AI mode
```
这只说明配置已读取；顶部“AI 已配置”也不等于模型调用成功。真实生成成功后顶部会显示“AI 调用成功”。若任何阶段失败，结果页会醒目标记 Demo 回退和原因。

注意：不要把 `.env` 文件发给别人。

## V1 工作流与人机边界

当前流程在确认后只调用一次模型生成完整结果，以减少网络往返和等待：

```text
用户输入原始情境
  -> 信息提取 Agent（姓名、关系、沟通目的）
  -> 用户确认或修改
  -> 一次模型调用：意图、关系、文化画像、表达与生成时风险自检
  -> 用户选择、修改并决定是否使用
```

AI 负责提取、分析、建议、生成和风险检查；用户负责确认事实、调整表达尺度、选择最终版本以及决定是否发送。文化画像仅作为软性参考，不能覆盖用户明确表达的事实、立场和限制。

## 首批典型场景

1. 向导师申请延期：重点验证权力差异、请求负担、解释长度和避免过度道歉。
2. 向同事表达异议：重点验证平等关系中的直接程度、合作信号和不同意见的清晰表达。

页面提供这两个场景的快捷示例，供首轮用户访谈和可用性测试使用。
